# Spec Delta

## ADDED Requirements

### Requirement: Tokens survive failed runs
The scheduled sync SHALL save the Garmin token file whenever it exists at the end of the job, including when a
later step failed, and SHALL restore the most recent saved tokens at the start of the next run.

#### Scenario: Run fails after authenticating
- **WHEN** a run logs in or refreshes its tokens and then fails in a later step
- **THEN** the token file is saved
- **AND** the next run restores it and does not perform a credential login

### Requirement: Bounded login frequency
The scheduled sync SHALL run at most once per day and never concurrently with itself.

#### Scenario: Manual dispatch during a scheduled run
- **WHEN** a run is dispatched while another sync is in progress
- **THEN** the new run waits until the first one finishes

### Requirement: Regenerated code is validated before publication
Files regenerated by the sync SHALL pass lint and the unit tests before being proposed, and SHALL be proposed as
a pull request rather than pushed directly to `main`.

#### Scenario: Regeneration breaks the tests
- **WHEN** the regenerated files make a unit test fail
- **THEN** the job fails and no pull request is opened or updated

#### Scenario: Nothing changed
- **WHEN** the regenerated files are identical to the committed ones
- **THEN** no pull request is opened
