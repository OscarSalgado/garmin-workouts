## Purpose

A Python CLI tool that manages structured training workouts and plans by syncing them to Garmin
Connect and Intervals.icu. It reads YAML-based workout/training-plan definitions, converts them into
Garmin and Intervals.icu API payloads, and handles scheduling, zone configuration, and calendar
management across both platforms.

## Requirements

### Requirement: SystemCapabilities

The system SHALL provide the following capabilities:
- YAML-driven workout and training plan definitions decouple the domain data from Python code, enabling non-developers to author plans
- step_generator (fanIn=61) is the central hub of workout construction — all sport-specific generators funnel into it, making it a critical integration point and potential bottleneck
- A _CompatClient compatibility shim wraps the external garminconnect library with a local fallback stub, isolating the rest of the codebase from the upstream API client's interface changes
- Strength exercise accessors and their tests are auto-generated (codegen pattern) from StrengthExercise definitions, reducing boilerplate and keeping code/config in sync
- Dual-platform sync (Garmin Connect + Intervals.icu) with independent client implementations allows either target to be used independently
- Training plan YAML files are organized by discipline, level, and mesocycle, enabling fine-grained plan composition without code changes
- Type dictionaries (WorkoutType, ActivityType, GolfType) are bootstrapped from live Garmin API responses and cached locally, reducing runtime API dependency for type resolution

## Technical Notes

- **Architecture Style**: Pipeline architecture with a configuration-driven code generation layer. YAML configs are parsed into domain models, transformed into API payloads, and dispatched to external REST APIs. A generator subsystem auto-produces Python accessor functions for strength exercises, suggesting a meta-programming/codegen pattern for the configuration layer.
- **Security Model**: Session-based authentication via the _CompatClient compatibility layer, which wraps the garminconnect library or falls back to a local client. Tokens are persisted to disk (dump/load) and loaded from JSON strings (loads). MFA/two-factor login is supported via a two-step resume_login flow. Intervals.icu uses API key auth (inferred from IntervalsAPI.patch/put hub functions). No OAuth or JWT; credentials are stored as serialized token files.
- **External Integrations**: Garmin Connect (workout management, scheduling, biometric zones, calendar, activity download, training plans), Intervals.icu (workout/event bulk upload, athlete sport settings, wellness data, activity streams), garminconnect Python library (optional external auth dependency with internal fallback stub), Race search API (running event discovery)
